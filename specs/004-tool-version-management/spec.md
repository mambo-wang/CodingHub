# 功能规格说明：工具版本管理

**功能分支**：`004-tool-version-management`

**创建日期**：2026-06-04

**状态**：已澄清

**输入**：用户描述："优化添加工具和修改工具页面：1：创建工具支持输入版本号。一个工具只有一个版本，如果需要更新版本则修改工具重新输入版本。2 修改工具支持文件删除和重新上传"

## Clarifications

### Session 2026-06-04

- Q: 版本号唯一性范围如何界定？ → A: 同用户下唯一（同一用户在同一分类中不能创建同名工具，但不同用户可以创建同名工具）
- Q: 修改工具时文件上传策略？ → A: 同名文件替换，不同名文件追加；用户可手动删除已有文件

**技术背景**：CodingHub是一个全栈 Web 应用，后端使用 Java 17 / Spring Boot 3.2.5，前端使用 Vue 3 / TypeScript。数据存储使用 MySQL 8.x，认证使用 JWT。

## 用户场景与测试 *（必须）*

### 用户故事 1 - 创建工具时输入版本号（优先级：P1）

用户在上传播工具时，需要为工具指定一个版本号，便于追踪工具的演进历史。用户输入版本号后，系统保存并展示该版本信息。

**为何此优先级**：版本号是工具管理的基础数据，用户必须能够在创建工具时指定版本。

**独立测试**：可通过创建工具流程独立测试——用户输入工具名称、描述、版本号并提交，系统保存并返回版本信息。

**验收场景**：

1. **假设** 用户已登录并进入"创建工具"页面，**当** 用户填写工具名称、描述并输入版本号"1.0.0"，**那么** 系统应保存该工具及其版本号，并在工具详情页显示版本号
2. **假设** 用户已登录并进入"创建工具"页面，**当** 用户提交时未填写版本号，**那么** 系统应提示"版本号不能为空"
3. **假设** 用户已登录并进入"创建工具"页面，**当** 用户输入格式错误的版本号（如"abc"），**那么** 系统应提示"版本号格式不正确，请使用标准格式（如 1.0.0）"

---

### 用户故事 2 - 修改工具时管理文件（优先级：P1）

用户修改已上传的工具时，需要能够删除已有的附件文件，并重新上传新的文件版本。上传文件时采用智能策略：同名文件自动替换，不同名文件追加到列表。

**为何此优先级**：文件管理是工具维护的核心功能，用户必须能够更新工具的附件资源。

**独立测试**：可通过修改工具流程独立测试——用户进入工具编辑页，删除现有文件，上传新文件，系统保存更新后的文件列表。

**验收场景**：

1. **假设** 用户拥有某工具的编辑权限并进入"修改工具"页面，**当** 用户点击现有文件旁的"删除"按钮，**那么** 系统应从文件列表中移除该文件，并删除服务器端存储的文件
2. **假设** 用户在修改工具页面，**当** 用户上传一个与现有文件同名的文件，**那么** 系统应替换现有文件（覆盖更新）
3. **假设** 用户在修改工具页面，**当** 用户上传一个与现有文件不同名的文件，**那么** 系统应将新文件追加到文件列表
4. **假设** 用户在修改工具页面，**当** 用户删除所有文件后不重新上传直接保存，**那么** 系统应允许保存（工具可以不包含文件）

---

### 用户故事 3 - 工具版本唯一性保证（优先级：P2）

每个工具在同一时间只能有一个版本号。如需更新版本，用户需进入修改工具页面重新输入新版本号。

**为何此优先级**：确保版本号的唯一性和可追溯性，避免版本混乱。

**独立测试**：可通过版本更新流程测试——用户修改工具时更改版本号，系统保存新版本号，旧版本号不再出现在工具记录中。

**验收场景**：

1. **假设** 用户已有一个版本为"1.0.0"的工具，**当** 用户进入修改工具页面并将版本号改为"2.0.0"并保存，**那么** 系统应更新工具版本号为"2.0.0"，工具详情页显示新版本号
2. **假设** 用户A已有一个名为"图像识别工具"的工具，**当** 用户B尝试创建一个同名"图像识别工具"（使用任意版本号），**那么** 系统应允许创建（因为不同用户可以创建同名工具）

---

### 边界情况

- 当版本号格式不正确时，系统应提供明确的格式提示
- 当删除文件时，应有确认提示避免误操作
- 当上传大文件时，应显示上传进度并设置合理超时
- 当网络中断导致上传失败时，应支持断点续传或重新上传
- 当工具名称为空时，应阻止提交

## 需求 *（必须）*

### 功能需求

- **FR-001**：系统必须允许用户在创建工具时输入版本号
- **FR-002**：版本号字段为必填项，提交时必须填写
- **FR-003**：版本号必须符合标准格式（语义化版本 SemVer，如 1.0.0、2.1.3-beta）
- **FR-004**：系统必须在工具详情页显示工具版本号
- **FR-005**：系统必须允许用户在修改工具时删除已有文件
- **FR-006**：系统必须允许用户在修改工具时上传新文件
- **FR-007**：删除文件时必须同步删除服务器端存储
- **FR-008**：同一用户在同一分类下不能创建同名工具（版本号唯一性范围：同用户+同分类）
- **FR-009**：上传文件时，同名文件自动替换，不同名文件追加到列表

### 安全需求

- **SR-001**：所有用户输入必须经过 XSS 防护处理（XssSanitizer.sanitize()）
- **SR-002**：文件删除操作必须验证用户权限（仅工具创建者或管理员可删除）
- **SR-003**：文件上传必须验证文件类型和大小（后端需校验）
- **SR-004**：敏感操作端点必须要求 JWT 认证

### 性能需求

- **PR-001**：文件上传接口 p95 延迟 < 5s（针对 50MB 以内的文件）
- **PR-002**：文件列表查询 p95 延迟 < 200ms
- **PR-003**：前端页面加载 < 1.5s

### 关键实体 *（如功能涉及数据则包含）*

- **Tool（工具）**：代表用户上传的 AI 工具，包含 name（名称）、content（描述）、version（版本号）、category_id（分类）、uploader_id（上传者）、status（状态）、created_at、updated_at
- **ToolFile（工具文件）**：代表工具的附件文件，包含 tool_id（关联工具）、file_path（存储路径）、file_name（原始文件名）、file_size（文件大小）、created_at

**Entity 关系**：

```
User (1) ─────< Tool (多)
Tool (1) ─────< ToolFile (多)
Category (1) ─────< Tool (多)
```

## API 契约 *（如涉及 API）*

### RESTful 端点

| 方法 | 路径 | 描述 | 认证 |
|------|------|------|------|
| GET | /api/tools | 获取工具列表 | 可选 |
| GET | /api/tools/{id} | 获取工具详情（含版本号） | 可选 |
| POST | /api/tools | 创建工具（含版本号） | 必须 |
| PUT | /api/tools/{id} | 更新工具（含版本号） | 必须 |
| DELETE | /api/tools/{id} | 删除工具及关联文件 | 必须 |
| POST | /api/tools/{id}/files | 上传工具文件 | 必须 |
| DELETE | /api/tools/{id}/files/{fileId} | 删除工具文件 | 必须 |

### 请求/响应格式

**创建工具请求体示例**：

```json
{
  "name": "图像识别工具",
  "content": "这是一个图像识别工具",
  "categoryId": 1,
  "version": "1.0.0"
}
```

**更新工具请求体示例**：

```json
{
  "name": "图像识别工具",
  "content": "更新了描述内容",
  "categoryId": 1,
  "version": "2.0.0"
}
```

**成功响应**：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "name": "图像识别工具",
    "version": "1.0.0",
    "files": [
      {
        "id": 1,
        "fileName": "readme.pdf",
        "fileSize": 102400
      }
    ]
  }
}
```

**错误响应**：

```json
{
  "code": 400,
  "message": "Bad Request",
  "data": null
}
```

## 技术约束

- **后端**：Java 17, Spring Boot 3.2.5, Spring Data JPA
- **前端**：Vue 3, TypeScript (strict mode), Vite
- **数据库**：MySQL 8.x
- **认证**：JWT（Access Token 30天，Refresh Token 90天）

- **测试覆盖率**：≥ 80%（新代码）

## 假设

- 用户使用标准语义化版本号格式（SemVer），如 1.0.0、2.1.3-beta
- 工具版本号唯一性范围：同一用户 + 同一分类（即同一用户在同一分类中不能有同名工具）
- 不同用户可以创建同名工具
- 文件删除操作需要前端二次确认
- 文件上传大小限制为 50MB（与现有系统保持一致）
- 工具可以不包含任何文件
- 版本号变更后旧版本记录不再保留（系统只记录最新版本）
- 文件上传策略：同名文件替换，不同名文件追加
