# Feature Specification: AI 工具广场

**Feature Branch**: `001-ai-tool-square`

**Created**: 2026-05-29

**Status**: Draft

**Input**: User description: "创建一个AI工具广场项目，可以上传skill mcp等工具，上传时写markdown介绍，填写上传人名字，UI参考skillhub.cn，使用frontend-design完善UI设计，前端使用vue3后端使用gradle+springboot的组合，数据库使用mysql（已安装，账号密码都为root）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 浏览工具广场首页 (Priority: P1)

访客（未登录用户）进入工具广场首页，浏览所有已上传的AI工具，按照分类、热度或最新时间排序，快速找到自己需要的工具。

**Why this priority**: 工具广场的核心价值是帮助用户发现工具，如果无法浏览就谈不上任何价值。

**Independent Test**: 可以通过清空浏览器缓存后直接访问首页，验证是否能在不登录的情况下浏览工具列表，并能完成工具搜索和筛选。

**Acceptance Scenarios**:

1. **Given** 用户打开工具广场首页，**When** 页面加载完成，**Then** 展示工具列表，包含工具名称、简介、分类标签、贡献者信息
2. **Given** 用户在工具列表页，**When** 点击分类筛选标签，**Then** 只展示该分类下的工具
3. **Given** 用户在工具列表页，**When** 在搜索框输入关键词并回车，**Then** 展示匹配名称或描述的工具
4. **Given** 用户在工具列表页，**When** 点击某个工具卡片，**Then** 打开工具详情页

---

### User Story 2 - 查看工具详情 (Priority: P1)

用户点击工具卡片进入详情页，查看该工具的完整 Markdown 介绍文档，包括功能说明、使用方式、配置参数等，并了解上传者和上传时间。

**Why this priority**: 用户在决定是否使用某个工具前，必须能够详细了解该工具的功能和使用方法。

**Independent Test**: 点击任意工具卡片，能看到完整的 Markdown 渲染后的介绍内容，且包含上传者和时间信息。

**Acceptance Scenarios**:

1. **Given** 用户在工具详情页，**When** 页面加载完成，**Then** 展示工具名称、完整 Markdown 渲染内容、上传者姓名、上传时间、分类标签
2. **Given** 用户在工具详情页，**When** 滚动查看 Markdown 内容，**Then** 代码块、表格、列表等元素正确渲染

---

### User Story 3 - 上传新工具 (Priority: P1)

登录用户点击"上传工具"按钮，填写工具基本信息（工具名称、分类、Markdown 介绍文档、上传者姓名），提交后工具出现在广场列表中。

**Why this priority**: 上传工具是工具广场的核心功能，没有贡献者上传新工具，广场就无法运转。

**Independent Test**: 登录后填写表单提交新工具，可以在工具列表页和详情页看到刚刚上传的工具。

**Acceptance Scenarios**:

1. **Given** 已登录用户点击"上传工具"按钮，**When** 页面跳转到上传表单，**Then** 展示必填字段：工具名称、分类、Markdown 介绍、上传者姓名
2. **Given** 用户填写上传表单，**When** 填写工具名称并选择分类后，**Then** 表单实时验证字段格式
3. **Given** 用户填写上传表单，**When** 点击"提交"按钮且所有必填字段有效，**Then** 显示上传成功提示，新工具出现在广场列表
4. **Given** 用户填写上传表单，**When** 某必填字段为空时点击"提交"，**Then** 显示字段验证错误提示，不提交表单

---

### User Story 4 - 用户认证与登录 (Priority: P2)

用户需要登录后才能上传工具。未登录用户可以浏览但无法上传。系统支持邮箱密码注册和登录。

**Why this priority**: 区分工具贡献者身份是追溯和质量把控的基础，同时需要防止恶意上传。

**Independent Test**: 访客无法访问上传表单但可以访问工具列表；注册登录后可以访问上传表单。

**Acceptance Scenarios**:

1. **Given** 访客访问工具广场，**When** 点击"上传工具"按钮，**Then** 跳转到登录/注册页面
2. **Given** 用户在登录页面，**When** 输入正确的邮箱和密码并点击登录，**Then** 登录成功，跳转回工具广场
3. **Given** 用户在注册页面，**When** 输入有效邮箱和密码并确认，**Then** 注册成功并自动登录，跳转到工具广场

---

### User Story 5 - 管理我上传的工具 (Priority: P3)

登录用户可以在个人中心查看自己上传的所有工具列表，并对工具进行编辑或删除操作。

**Why this priority**: 贡献者需要能够维护自己上传的工具内容，修正错误或下架不需要的工具。

**Independent Test**: 登录后访问个人中心，可以看到自己上传的工具列表，并可以对任意一个进行编辑或删除操作。

**Acceptance Scenarios**:

1. **Given** 已登录用户访问个人中心，**When** 点击"我的工具"标签，**Then** 展示当前用户上传的所有工具列表
2. **Given** 用户在"我的工具"列表中，**When** 点击某个工具的"编辑"按钮，**Then** 打开编辑表单并预填充现有内容
3. **Given** 用户在"我的工具"列表中，**When** 点击某个工具的"删除"按钮，**Then** 弹出确认对话框，确认后工具从列表和广场中移除

---

### Edge Cases

- Markdown 介绍包含恶意脚本时，系统必须进行内容过滤和转义，防止 XSS 攻击
- 用户名或工具名称包含特殊字符（ emoji、超长字符串）时，需要限制长度和字符范围
- 上传的 Markdown 包含大图片链接时，详情页需要正确处理图片大小防止布局错乱
- 同一工具名称重复上传时，需要提示用户工具名称已存在
- 网络异常或数据库错误时，用户应看到友好的错误提示而非技术细节

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持访客浏览工具列表，包含名称、简介、分类、上传者信息
- **FR-002**: 系统 MUST 支持工具列表按分类筛选和多关键词搜索
- **FR-003**: 系统 MUST 支持工具列表按最新上传时间和热度排序
- **FR-004**: 系统 MUST 支持工具详情页展示完整 Markdown 渲染内容
- **FR-005**: 系统 MUST 支持已登录用户上传新工具，包含：名称、分类、Markdown 介绍、上传者姓名
- **FR-006**: 系统 MUST 在上传前验证所有必填字段，字段为空或格式错误时给出明确提示
- **FR-007**: 系统 MUST 支持用户注册和登录（邮箱+密码）
- **FR-008**: 系统 MUST 区分登录用户和访客，未登录用户禁止访问上传功能
- **FR-009**: 已登录用户 MUST 能在个人中心查看、编辑、删除自己上传的工具
- **FR-010**: 系统 MUST 在所有用户输入场景防止 XSS 注入攻击
- **FR-011**: 系统 MUST 限制工具名称和用户名的长度为 1-100 字符，只允许字母、数字、中文、常用符号

### Key Entities *(include if feature involves data)*

- **User（用户）**: 代表在系统注册的贡献者。属性：用户ID（主键）、邮箱、密码（加密存储）、用户名、注册时间、最后登录时间。
- **Tool（工具）**: 代表一个上传的 AI 工具。属性：工具ID（主键）、工具名称、分类、Markdown 介绍内容、上传者ID（外键关联User）、上传时间、更新时间、状态（正常/已删除）。
- **Category（分类）**: 工具的分类标签。属性：分类ID（主键）、分类名称、分类图标（可选）、排序权重。预置分类包括：Skill、MCP、API、Prompt、其他。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能在 3 秒内打开工具广场首页并看到工具列表
- **SC-002**: 用户能在首页通过 3 次点击内找到目标工具或到达目标分类
- **SC-003**: 工具详情页的 Markdown 内容（最多 5000 字）在 2 秒内完成渲染
- **SC-004**: 上传表单提交后，新工具在 5 秒内出现在工具列表中
- **SC-005**: 用户注册和登录操作在 3 秒内完成
- **SC-006**: 工具搜索返回相关结果的时间不超过 1 秒
- **SC-007**: 系统能同时支撑 100 个并发用户浏览工具列表而不出现明显延迟

## Assumptions

- 用户上传的工具介绍内容（Markdown）存储在数据库 TEXT 字段中，假设最大长度为 5000 字符
- 系统采用单体架构，前端 Vue3 和后端 Spring Boot 部署在同一服务器上
- 用户密码使用 BCrypt 或 Argon2 算法加密存储
- 工具广场上线初期不接入第三方登录（如 GitHub OAuth），仅支持邮箱密码
- 工具分类采用预定义枚举方式，不支持用户自定义分类
- 不考虑文件上传（如工具图标、附件），所有内容均为文本
- 工具热度排序依据上传时间（越新越热），暂不引入点赞、下载量等指标
