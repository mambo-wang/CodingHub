## 背景

CodingHub 中「评论、收藏、点赞」这类互动能力被多个领域模块复用：工具（TOOL）、论坛帖子（FORUM_POST）、微课视频（VIDEO）。历史上这类功能曾被分散实现，导致逻辑重复、计数不一致、匿名用户处理不统一等问题。

## 决策

**任何涉及评论、收藏、点赞的功能，必须复用已有的「统一互动」实现，不得为新模块重复造轮子。** 新增可互动的资源类型时，应扩展已有的枚举和 Service，而不是新建一套独立的 Controller/Service/Repository/Model。

## 已有实现（参考基准，以工具互动为蓝本）

统一互动实现已经过工具、论坛、视频三套模块的打磨，是后续功能的参考基准：

- 枚举 `model/TargetType`（值：`TOOL`、`FORUM_POST`、`VIDEO`）——决定互动作用于哪类资源
- 实体：`model/UnifiedLike`、`model/UnifiedComment`、`model/UnifiedFavorite`（按 targetType + targetId 通用建模，不再每类资源各建一张表）
- 服务层：`service/UnifiedLikeService`、`service/UnifiedCommentService`、`service/UnifiedFavoriteService`
- 控制器：`controller/UnifiedInteractionController`（`/api/v1/interactions`）
- DTO：`dto/InteractionRequest`、`dto/InteractionResponse`

### 统一能力清单（新增功能时直接复用，不要重写）

1. **点赞** `POST /api/v1/interactions/likes` + 状态查询 `GET /api/v1/interactions/likes/status`
   - 同时支持登录用户（按 userId）与匿名用户（按 IP 哈希 `ipHash`），Toggle 语义自动增减计数
2. **评论** `POST /api/v1/interactions/comments`（支持顶层 + 嵌套回复，parentId/rootId）、分页 `GET ...`，删除 `DELETE .../{id}`（带 owner/admin 权限校验）
   - 评论内容统一经过 `XssSanitizer.sanitize()` 防护
3. **收藏** `POST /api/v1/interactions/favorites`（强制登录）、收藏列表 `GET ...`、`GET .../status`

计数维护（likeCount / commentCount）由统一 Service 在对应实体上自增自减，并触发 `updateScore()` 评分刷新。

## 如何扩展（新增一种可互动资源的标准做法）

1. 在 `TargetType` 枚举中新增枚举值（如 `KNOWLEDGE`）；
2. 在 `UnifiedLikeService` / `UnifiedCommentService` / `UnifiedFavoriteService` 的 `validateTargetExists`、`updateLikeCount`、`incrementCommentCount` 等 `switch (targetType)` 分支中补充新分支；
3. 确保目标实体存在 `likeCount` / `commentCount` 字段及对应 Repository 查询方法；
4. 如需返回收藏列表的具体资源 DTO，在 `UnifiedFavoriteService.getMyFavorites` 中补充对应 `buildXxxFavorites` 分支。

**不要**为新模块新建 `XxxLikeController`、`XxxCommentService` 或在目标实体里再挂一套 `xxxLikes` 子表。

## 替代方案（被否决）

- 每类资源各自实现 `ToolLike`/`ForumLike`/`VideoLike` 式独立实体与 Service：已存在 `model/ToolLike` 等旧实现，属于历史债务，新功能不再沿用。
- 把互动逻辑写进各业务 Controller：会破坏分层，且匿名/计数/权限逻辑无法复用。

## 约束来源

- AGENTS.md 第 6 节「禁止循环依赖 / 单向依赖 controller → service → repository → model」
- 软删除 `status = DELETED`，统一 Service 在 `validateTargetExists` 中已按 NORMAL 状态过滤
