## 背景

CodingHub 的 AI 工具市场需要对接多种 LLM 服务（OpenAI、Claude、本地模型等），需要一个标准化的 Agent 通信协议来屏蔽各服务的差异。

## 决策

采用 MCP (Model Context Protocol) 作为统一的 Agent 通信协议，而非为每个 LLM 服务编写独立的适配器。

## 备选方案

- **自建 RPC 协议**：放弃，维护成本高且生态封闭
- **OpenAI Function Calling**：放弃，与特定厂商绑定，无法对接非 OpenAI 模型
- **LangChain Tool 抽象**：放弃，引入重依赖且抽象层过多

## 收益

- 工具只需实现一次 MCP Tool 定义，即可被任何兼容 MCP 的 Agent 调用
- 标准化了工具注册、调用、错误处理的流程
- 社区生态可复用（QoderWork、Claude Desktop 等原生支持 MCP）

## 影响

工具市场模块和 RAG 服务模块的对外接口统一收敛到 MCP 协议层，降低了后续对接新 LLM 服务的成本。
