## OpenSpec 方案转向：MySQL→PostgreSQL 单向迁移 → 双库共存（配置切换）
用户决定的方向变更。原 change `migrate-mysql-to-postgresql`（7/23 创建）已重命名为 `dual-database-config-driven`，四份产物（proposal/design/specs/database-persistence/tasks）全部改写为双库共存方案，`openspec validate --strict` 通过。

核心设计（用户明确选定「写法 1：单文件多文档 yaml」）：
- `build.gradle`：mysql-connector-j 与 postgresql **共存**，非替换。
- `application.yml`：顶部通用配置 + `---` 分隔 `on-profile: mysql` / `postgresql` 两段各提供 `spring.datasource`；**移除硬编码 MySQLDialect**，交由 Hibernate 6 按 JDBC 连接自动探测方言（同一份实体两库都能跑）。
- 开启 `hibernate.globally_quoted_identifiers=true`。
- `User.java`：**保留** `@Table(name = "`user`")` 反引号（未去）。原因：H2 `MODE=MySQL` 把双引号当字符串字面量、只有反引号是标识符引号；MySQL 下 `user` 非保留字、反引号无害；**PostgreSQL 下由 `globally_quoted_identifiers` 把反引号归一化为双引号 `"user"`（实测 PG 建表成功）**。所以最终方案是"反引号 + 仅在 postgresql profile 开全局引号"，而非"去反引号"。
- `globally_quoted_identifiers=true` **仅放在 postgresql profile 段**（不放 common/test）：H2 `MODE=MySQL` 下双引号会被当字符串导致建表失败。
- 7 处 `columnDefinition = "TEXT"` 改小写 `"text"`：PG 下全局引号会把 `TEXT` 引为 `"TEXT"`（无效，PG 内置类型是小写 `text`）；小写 `text` 被引为 `"text"`（有效）。MySQL/H2 大小写不敏感无影响。
- 默认 profile = mysql（向后兼容），`--spring.profiles.active=postgresql` 切换。
- 业务代码零改动（nativeQuery 零命中、IDENTITY/字符串枚举均兼容）。
- 初始化脚本：`scripts/init-db-postgres.sql` 改为**仅种子**（PG 权威 Schema 由 Hibernate ddl-auto 生成，手写 DDL 易与实体不一致已踩坑）；`Makefile` 新增 `db-pg`（建库）/ `db-pg-seed`（种子），`init-db-windows.ps1` 按 `DB_TYPE` 切换。

## 修复 Bug：工具广场卡片浏览量恒为 0
- 根因：`ToolService.getToolById`（工具详情接口 `/api/v1/tools/{id}` 后端）从未调用 `incrementViewCount`，且没有任何 controller/MCP 路径触发已有的 `incrementViewCount(toolId)`，导致 `view_count` 一直停在种子值 0。
- 对比：兄弟模块 `ForumPostService.getPostById`、`VideoService.getVideoDetail` 都在拉详情时自增浏览量，ToolService 漏了这一步。
- 修复：`ToolService.getToolById` 改为 `@Transactional` 并在返回 DTO 前 `tool.incrementViewCount(); toolRepository.save(tool);`（与论坛/视频一致）。前端卡片直接读 `tool.viewCount`，无需改动。
- 验证：新增 `backend/src/test/java/com/iaihub/toolbox/service/ToolViewCountTest.java`（独立文件，因 `build.gradle` 把 `ToolServiceTest.java` 排除编译，且其构造参数与真实 ToolService 构造签名不符），测试 `getToolById` 后将 5→6 并调用 save，运行通过。

## 修复中的连带问题：Tool.updateScore() 空指针
- 现象：上线后 `/api/v1/tools/{id}` 返回 HTTP 500，日志 NPE：`Tool.updateScore() line 102: this.downloadCount.intValue()`，downloadCount 为 null。
- 根因：种子工具行的 `download_count` 列为 NULL；`Tool.updateScore()` 用 `BigDecimal.valueOf(this.downloadCount)` 自动拆箱 null → NPE。`@Builder.Default` 的 `=0` 只在 Lombok Builder 生效，**Hibernate 从 DB 加载会直接把字段置为 null**，绕过默认值。原 getToolById 不调 incrementViewCount，故此前未触发；本次改动首次在详情接口触发 updateScore 而暴露。
- 修复：`Tool.updateScore()` 改为对 view/download/like/favorite/comment 五个计数做 null→0 的空安全处理。同类风险（incrementLikeCount 等）一并消除。
- 回归验证：重启后端，两次 GET `/api/v1/tools/1` 返回 viewCount 1→2，列表卡片同步为 2，无 500；ToolViewCountTest 仍通过。

## 修复 Bug：工具附件下载报错（HTTP 500）
- 根因：`ToolFileController.downloadFile` → `ToolFileService.downloadFile` → `tool.incrementDownloadCount()` → `Tool.incrementDownloadCount()` 里 `this.downloadCount++` 对 DB 加载的 null `Integer` 自动拆箱 → NPE。`Tool` 所有 `increment*Count()`/`decrement*Count()` 方法都有同样的 null 不安全写法（view/like/comment/download/favorite），Hibernate 从库加载会把计数字段置为 null，绕过 `@Builder.Default` 的 0 默认值。
- 连带问题1：`getFileInputStream` 又调用了一次 `downloadFile`，导致每次下载下载量被自增两次，且该方法是 `@Transactional(readOnly=true)` 却执行写操作。已改为仅按 id 取文件实体并打开流，不再自增。
- 连带问题2：`ToolFileRepository.incrementDownloadCount` 的 JPQL 为 `download_count = download_count + 1`，当列值为 NULL 时 `NULL+1=NULL`，下载量永远不增长。改为 `COALESCE(tf.downloadCount, 0) + 1`。
- 修复文件：`model/Tool.java`（所有 increment/decrement 方法 null 安全）、`service/ToolFileService.java`（getFileInputStream 不再重复自增）、`repository/ToolFileRepository.java`（COALESCE）。
- 验证：重启后端后 `GET /api/v1/tools/6/files/6/download` 返回 200 与文件内容；tool 6 downloadCount 0→1→2（单次自增，无重复）；新增 `model/ToolIncrementNullSafeTest` 与既有 `ToolViewCountTest` 均通过。
